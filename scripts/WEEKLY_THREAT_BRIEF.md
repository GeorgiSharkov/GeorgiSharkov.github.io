# Weekly CyberShark threat brief

Run Monday at 09:00 Europe/London through the Codex task automation.

1. Fetch origin/main and integrate new commits safely. Preserve unrelated local work. Read the existing PHP2Shell and AI escape case studies for the visual style and level of explanation.
2. Research threats disclosed or materially updated during the previous seven days. Prioritise verified exploitation, new KEV entries, significant campaigns, and high-impact incidents. Use original vendor advisories, researcher disclosures, CISA, NCSC, CERTs, and official incident reports. Check event dates separately from publication dates and select a topic not already covered in threat-articles.json.
3. Create one original, substantial SOC article as a standalone HTML page in the repository. Cite sources beside factual claims and include a source list at the bottom. Distinguish confirmed evidence, source allegations, and analyst inference. Never fabricate CVEs, IOCs, screenshots, telemetry, exploit status, patch versions, or commands. If no new incident warrants a brief, cover a verified material update to an existing threat and make that scope explicit.
4. Explain the technical mechanism, affected assets and prerequisites, attack chain, an evidence-based timeline, relevant ATT&CK mappings with links, collection priorities and log sources, investigation steps, tested or clearly labelled query starters for applicable SOC platforms, false-positive considerations, containment, remediation, validation, and a concise analyst checklist. Label illustrative events and query assumptions. Use defensive commands and sanitised examples. Do not present invented example telemetry as incident evidence.
5. Include a bespoke HTML/SVG attack-path diagram, timeline, or evidence map. Use actual screenshots only when available and permitted; attribute them. Maintain readable desktop/mobile layouts and the site's fonts, colours, navigation, consent tag, analytics setup, and favicon. Link back to threat-briefs.html and the homepage.
6. Add the published article's title, local URL, ISO publication date, category, concise summary, and tags to threat-articles.json. Run python scripts/build_threat_articles.py to update the homepage alert tab, latest article feature, and archive. Do not replace the archive or delete older articles.
7. Validate all source URLs, local links and assets, date accuracy, HTML structure, query syntax/assumptions, mobile layout, and git diff --check. Check JavaScript syntax if edited. Ensure no unrelated files or credentials enter the commit.
8. Commit the article and catalogue/generated page changes, fetch and integrate latest main without force-pushing, and push HEAD:main to origin. Publishing each weekly article is authorised by the user. Watch the final GitHub Pages deployment and verify the live article, homepage tab, and archive serve the new content. Report article title, sources, commit, deployment status, and any genuine blocker. Never claim publication if it did not complete.

The task runs on the connected local Codex host. If the host is unavailable, publication can be delayed until the automation can execute. Keep the last successfully published article visible.
